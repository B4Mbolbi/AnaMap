Судя по скриншоту, проблема очевидна: **левая панель превратилась в «швейцарский нож», где всё валится в одну длинную колонку**. Фильтры, статистика, экспорт, связи, даты, категории — всё вперемешку. Глаз не знает, за что зацепиться.

Идея с **вертикальными вкладками (табами) слева** — абсолютно правильная. Это разгрузит интерфейс и сделает его похожим на профессиональный инструмент (как в Figma, Notion или Grafana).

Ниже — **готовый промпт для нейросети**, который переведёт текущий сайдбар на вкладочную систему и добавит вкладку проектов.

---

## ПРОМПТ (копировать целиком)

```
# Задача: реорганизовать левый сайдбар AnaMap в систему вертикальных вкладок (Tabs) + добавить вкладку «Проекты»

## Контекст
AnaMap — SPA на vanilla JS + Leaflet без сборщика (см. index.html, css/, js/).
Сейчас левый сайдбар (aside.sidebar) — это одна длинная колонка, куда свалено всё:
фильтры по типам, фильтр по статусу, кнопки экспорта/импорта, фильтр по типу связи,
фильтры по датам, статистика по типам, таймлайн, список событий, статистика по статусам.
Это создаёт визуальный шум и мешает работать.

Задача — разбить содержимое сайдбара на логические вкладки (tabs) с вертикальным переключателем.
Дизайн должен остаться в тёмной теме, использовать существующие CSS-переменные из css/variables.css
(--bg-surface, --bg-card, --border-default, --text-primary, --text-muted, --accent-blue и т.д.).
Никаких новых зависимостей и сборщиков.

## Архитектура вкладок

Слева — узкая вертикальная полоса с иконками вкладок (как в VS Code / Figma).
Справа от неё — панель с содержимым активной вкладки.

Вкладки (сверху вниз):
1. 🔍 **Фильтры** (Filters) — фильтры по типам, статусу, датам, типу связи, кнопка «Очистить всё».
2. 📊 **Статистика** (Stats) — статистика по типам + статистика по статусам + таймлайн.
3. 📋 **События** (Events) — список событий по категориям (как сейчас в event-list-panel),
   с поиском по тексту (новое поле) и сортировкой (по дате / по статусу).
4. 🔗 **Связи** (Links) — список всех связей текущего проекта (текстовый список:
   «Событие A → Событие B, тип: Следствие»), кнопка «Удалить связь», кнопка
   «Экспорт связей JSON/CSV», фильтр по типу связи.
5. 📁 **Проекты** (Projects) — управление проектами: список проектов, создать,
   переименовать, удалить, экспорт/импорт проекта. Текущий активный проект подсвечен.
6. ⚙️ **Данные** (Data) — экспорт/импорт событий (JSON/CSV), импорт проекта, валидация,
   управление категориями и статусами (кнопки «+ Категория», «+ Статус»).

Вкладка «Проекты» должна быть первой по умолчанию? Нет — по умолчанию активна «Фильтры»,
но если проектов больше одного или это первый запуск — можно показать «Проекты».

## Что нужно сделать

      <section class="sidebar-panel" data-panel="projects">...</section>
      <section class="sidebar-panel" data-panel="data">...</section>
    </div>
  </aside>
  ```
- Внутри каждой панели оставить существующие id элементов (filter-types, stats-types,
  stats-status, timeline-container, event-list-container, кнопки экспорта и т.д.),
  чтобы существующий JS продолжал работать без переписывания логики.

  - Для «Связи»: `<div id="links-list"></div>`, кнопки экспорта связей.

### 2. CSS (css/sidebar.css)
- Добавить стили для `.sidebar`, `.sidebar-tabs`, `.sidebar-tab`, `.sidebar-panels`, `.sidebar-panel`.
- Вертикальный переключатель: ширина ~56px, иконки по центру, активная вкладка
  подсвечена через `--accent-blue` (фон/бордер), hover — через `--bg-card`.
- Панель контента: `flex: 1`, `overflow-y: auto`, кастомный скроллбар (уже есть в scrollbar.css).
- Плавное переключение: `.sidebar-panel { display: none; } .sidebar-panel.active { display: block; }`

- Использовать ТОЛЬКО переменные из variables.css. Никаких хардкод-цветов вроде #2a2e38.
- Адаптив: при ширине < 900px — вкладки превращаются в горизонтальную полосу сверху

### 3. JS: компонент вкладок (js/components/sidebarTabs.js — новый файл)
- `initSidebarTabs()` — навесить обработчики на `.sidebar-tab`, переключать `.active`

- `switchSidebarTab(name)` — программное переключение (для вызовов из кода,
  например «открыть вкладку Связи после создания связи»).
- Запоминать активную вкладку в `localStorage` (ключ `anemap_active_tab`), чтобы
  после перезагрузки открывалась та же.
- Подключить скрипт в index.html ПОСЛЕ компонентов, ДО app.js. Вызвать в `App.init()`.

### 4. JS: вкладка «Связи» (js/components/linksPanel.js — новый файл)
- `renderLinksPanel()` — читает `State.currentProject.links` (или `savedLinks`),
  для каждой связи находит события по id, рисует строку вида:
  «[Цвет типа] Описание A → Описание B (тип связи)» + кнопка «Удалить».
- Кнопка удаления вызывает `removeLink` / фильтрует `savedLinks` + `Storage.saveProject`.
- Кнопки «Экспорт связей JSON/CSV» — новые функции в `Export`:
  - `exportLinksJSON(links = State.links)` — уже есть, использовать.
  - `exportLinksCSV(links)` — добавить: колонки `ID, From, To, Type, FromDescription, ToDescription`.
- Фильтр по типу связи (если типы связей появятся; если нет — оставить селект
  «Все связи» и заготовку на будущее).
- Вызывать `renderLinksPanel()` при: инициализации, создании/удалении связи,
  переключении проекта.

### 5. JS: вкладка «Проекты» (js/components/projectsPanel.js — новый файл)

- Активный проект подсвечен (бордер `--accent-blue`).
- «Импорт проекта» — отдельный `<input type="file">`, вызывает `Export.importProjectJSON`.
- Все действия после мутации вызывают полный ререндер: `renderProjectSelect();`
  `renderProjectsPanel(); renderMap(); renderUI(); renderEventList(); renderLinksPanel();`
- (Если вкладка «Проекты» уже реализована как дропдаун в шапке из предыдущего промпта —
  оставить дропдаун как быстрый переключатель, а вкладку «Проекты» сделать расширенным

## Критерии приёмки

1. Сайдбар визуально разделён на вертикальный переключатель (иконки) и панель контента.
2. Переключение вкладок мгновенное, без перезагрузки, без потери состояния фильтров.
3. Вкладка по умолчанию — «Фильтры». Активная вкладка запоминается в localStorage.
4. Все существующие элементы (filter-types, stats-types, stats-status, timeline-container,
   event-list-container, кнопки JSON/CSV/Import/Validate, + Категория, + Статус,
   фильтр статуса, фильтры дат, фильтр типа связи) — на месте и работают как раньше.
5. Вкладка «Связи» показывает список связей текущего проекта; удаление связи из списка
   убирает её с карты и из localStorage. Экспорт связей JSON/CSV работает.
6. Вкладка «Проекты» показывает список проектов, позволяет создать/переименовать/удалить/
   экспортировать/импортировать. Переключение проекта мгновенно обновляет карту и все вкладки.
7. Вкладка «События» имеет поле поиска и сортировку; поиск фильтрует список, сортировка
   меняет порядок.
8. Никаких `alert()` для штатных операций (только confirm на удаление, prompt на имя).
9. Никаких хардкод-цветов в CSS — только переменные из variables.css.
10. Порядок скриптов в index.html: новые компоненты (sidebarTabs.js, linksPanel.js,
    projectsPanel.js) — после state.js/storage.js/helpers.js, до app.js. Вызов
    initSidebarTabs() в App.init() ДО renderMap/renderUI.

## Ограничения

- Не вводить сборщик, ES-модули, npm-зависимости.
- Не переписывать существующие модули целиком — только точечные правки (index.html,
  sidebar.css, добавление новых файлов, минимальные хуки в app.js и eventListRender.js).
- Не менять структуру события и схемы данных.
- Не ломать существующие фичи: карта, связи, тепловая карта, кластеры по годам,
  импорт/экспорт событий, кастомные категории/статусы, фильтры.
- Иконки — использовать эмодзи (🔍 📊 📋 🔗 📁 ⚙️) или простые inline SVG, без внешних
  библиотек иконок.
